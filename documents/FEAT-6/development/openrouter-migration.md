# FEAT-6 — Implementation: OpenRouter instead of `GEMINI_API_KEY`

This doc records exactly what changed to route the Gemini models through
OpenRouter. See `../plans/prd.md` for the motivation and decisions.

> **Follow-up:** the default model was later switched to a free model, with an
> 8192-token output cap, after a 402 in production. See `free-tier.md`.

## Files changed

| File | Change |
|---|---|
| `agent-runtime/src/agent/index.ts` | `createGoogleGenerativeAI` → `createOpenRouter`. Gemini entries in `PROVIDERS` now point at OpenRouter slugs. |
| `agent-runtime/src/agent/index.test.ts` | **New.** Pins the env var, endpoint, headers, model slugs and spec version. |
| `agent-runtime/package.json` | `-@ai-sdk/google`, `+@openrouter/ai-sdk-provider@^0.7.5`. |
| `package-lock.json` | Regenerated by `npm uninstall` / `npm install -w @repo/agent-runtime`. |
| `agent-runtime/.env.example` | `GEMINI_API_KEY` → `OPEN_ROUTER_API_KEY=YOUR_OPEN_ROUTER_API_KEY`. |
| `README.md`, `CLAUDE.md` | Env table and docs index. |

No call sites changed. `runTurn`, `subagentRunner`, `extractMemory` and
`createSkill` all resolve models through `pickProvider()` → `PROVIDERS[key]`,
and the keys are the same.

## The provider wiring

```ts
// src/agent/index.ts
const openrouter = createOpenRouter({
  apiKey: process.env.OPEN_ROUTER_API_KEY ?? '',
  headers: {
    'HTTP-Referer': 'https://andy770921-ai-agent.hf.space',
    'X-Title': 'LINE AI Agent',
  },
});

export const PROVIDERS: Record<string, LanguageModel> = {
  'gemini-2.5-flash': openrouter('google/gemini-2.5-flash'),
  'gemini-2.5-pro': openrouter('google/gemini-2.5-pro'),
  // claude-* / gpt-4o unchanged
};
```

- Base URL is the provider default, `https://openrouter.ai/api/v1`. Calls hit
  `/chat/completions`, the same endpoint as OpenRouter's fetch example.
- No `as unknown as LanguageModel` cast: the 0.7 line already returns
  `LanguageModelV1`, and `tsc` passes without it.
- To add another model, add a `PROVIDERS` entry with any slug from
  `GET https://openrouter.ai/api/v1/models`, then point `DEFAULT_MODEL` at it
  if it should be the default.

## Compatibility: why the 0.7 line specifically

`@mastra/core@0.10.15` depends on `ai@^4.3.16` (installed: 4.3.19). AI SDK 4
checks `model.specificationVersion === 'v1'` and throws `Unsupported model
version. AI SDK 4 only supports models that implement specification version
"v1"` otherwise. Before choosing a package, each candidate was run through a
mock harness: a local HTTP server imitating `/chat/completions` that returns
one tool call, then a final text, driven by a real Mastra `Agent` with one tool.

| Provider package | Spec | Result through Mastra 0.10 |
|---|---|---|
| `@openrouter/ai-sdk-provider@0.7.5` | v1 | ✅ tools sent on the wire, tool executed, final text returned, `HTTP-Referer` / `X-Title` sent |
| `@ai-sdk/openai@3.0.63` (locally installed) + `baseURL` | v3 | ❌ `Unsupported model version`, no request made |
| `@openrouter/ai-sdk-provider@1.x` | v2 | ❌ by construction (peer `ai ^5`) |

Do not bump `@openrouter/ai-sdk-provider` past `0.7.x` until Mastra is upgraded
to an `ai@5+`-based release. The `^0.7.5` range already prevents this, and
`index.test.ts` asserts `specificationVersion === 'v1'`.

## Live smoke test (needs a real key)

From the repo root, with `OPEN_ROUTER_API_KEY` set in `agent-runtime/.env`:

```bash
( set -a; . agent-runtime/.env; set +a
  curl -sS https://openrouter.ai/api/v1/chat/completions \
    -H "Authorization: Bearer $OPEN_ROUTER_API_KEY" \
    -H 'HTTP-Referer: https://andy770921-ai-agent.hf.space' \
    -H 'X-Title: LINE AI Agent' \
    -H 'Content-Type: application/json' \
    -d '{"model":"google/gemini-2.5-flash","messages":[{"role":"user","content":"Reply with exactly: pong"}]}' )
```

Expect HTTP 200 with `choices[0].message.content` ≈ `"pong"`.

- **401** means a bad or revoked key.
- **402** means OpenRouter wouldn't cover the request's estimated cost. That
  can be a low account balance (*"You requested up to N tokens, but can only
  afford M"*), the key's spending limit, or an expired key.

To exercise the whole agent, not just one request, use
`npm run smoke --workspace=@repo/agent-runtime`; see `free-tier.md`.

## Deployment

1. HF Space → Settings → Repository secrets: add `OPEN_ROUTER_API_KEY`.
2. Merge to `main`; `.github/workflows/hf-sync.yml` syncs and the Space rebuilds.
   The Docker build runs `npm install` from `package.json` (no lockfile), so it
   picks up `@openrouter/ai-sdk-provider@0.7.x`.
3. Send the bot a LINE message (once plain text, once a screenshot request to
   exercise `task_browser` tool calls). Confirm the request appears on the
   OpenRouter activity page under `LINE AI Agent`.
4. Delete the now-unused `GEMINI_API_KEY` secret.

**Rollback:** revert the FEAT-6 commit and re-add `GEMINI_API_KEY`.

## Known issues / follow-ups

- **Local lockfile drift (pre-existing, not caused by FEAT-6).**
  `package.json` pins `@ai-sdk/anthropic` and `@ai-sdk/openai` at `"1"`, but
  the root `package-lock.json` resolves them to 3.x, which produces v3 models
  that Mastra 0.10 rejects. Production is unaffected because the Docker build
  ignores the lockfile and installs 1.x. Locally, the `claude-*` / `gpt-4o`
  entries would fail at call time. Fix with
  `npm install @ai-sdk/anthropic@1 @ai-sdk/openai@1 -w @repo/agent-runtime`.
  After that, the "Cast needed: @ai-sdk/*@3" comment in `index.ts` can likely
  be dropped along with the casts.
- **Consolidate on OpenRouter.** `claude-sonnet-4-6` / `claude-haiku-4-5` /
  `gpt-4o` could become `openrouter('anthropic/claude-sonnet-4.6')` etc. (all
  slugs exist on OpenRouter), removing `@ai-sdk/anthropic`, `@ai-sdk/openai`,
  `ANTHROPIC_API_KEY` and `OPENAI_API_KEY`.
- **Fallbacks.** The provider accepts `models: [...]` for OpenRouter-side
  fallback (e.g. `gemini-2.5-flash` → `gemini-2.5-pro`) if upstream errors become
  a problem.
- **Langfuse cost.** Generations are still tagged `model: 'gemini-2.5-flash'`,
  so Langfuse prices them with Google's list price, not OpenRouter's billed
  amount. OpenRouter's dashboard is the source of truth for spend.
